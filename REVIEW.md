# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (original lines 33–37) | Compared whole integer minutes with `> 10` and did not convert timezone. For shift 09:30, punch-in at 09:40:01 gives 10 whole minutes; `10 > 10` is False → returns 0 instead of 10. Also broke for UTC timestamps. | Test with shift 09:30 and punch-in at 09:40:01 IST → 0 instead of expected 10 late minutes. | Convert punch-in to IST, compare `diff_sec > 600` (strictly > 10 min in seconds), return `diff_sec // 60` counted from shift start. |
| 2 | `compute_late_minutes` — overnight shifts | Did not account for overnight shifts (22:00–06:00) where a punch-in before 06:00 on the next calendar day belongs to the previous day's shift start. | Punch-in 05:30 Jul 7 for 22:00–06:00 shift compared against Jul 7 22:00 instead of Jul 6 22:00. | Added `get_attendance_date` helper; pass `date_str` to anchor shift_start on the correct calendar day. |
| 3 | `compute_work_hours` | Used Python's built-in `round()`, which performs banker's rounding (round-half-to-even) instead of half-up rounding required by R4. | Duration yielding 4.495000 h rounded to 4.50 or 4.49 depending on parity, failing the half-up rule. | Used `decimal.Decimal` with `ROUND_HALF_UP` for consistent half-up rounding to 2 decimal places. |
| 4 | `compute_overtime` | Returned any positive minutes without the 30-minute minimum (R3). Also placed shift_end on punch-in date for overnight shifts instead of the next calendar day. | 15 min of overtime returned 15 instead of 0; overnight shift end was 16 h in the past. | Advance shift_end to next calendar day for overnight shifts via `get_shift_window`; return minutes only when `>= 30`. |
| 5 | Startup / Indexes | No MongoDB indexes created at startup. | Concurrency tests allowed duplicate `emp_code` and `(emp_code, date)` records; queries produced COLLSCAN. | Implemented `init_db()` in FastAPI `lifespan` creating unique indexes on `emp_code` and `(emp_code, date)`, plus sort/filter indexes. Also added `employees.joined_on` for headcount queries. |
| 6 | `health` | Returned `{"status": "ok"}` unconditionally without checking MongoDB connectivity. | Stopping MongoDB still returned HTTP 200 on `/health` instead of required 503. | Added `client.admin.command("ping")` inside try/except, raising HTTP 503 on failure. |
| 7 | `create_employee` | Check-then-act race condition (`find_one` → `insert_one`); stored naive datetime for `created_at`; returned unformatted datetime (not epoch ms); lacked regex/shift validation. | Concurrent duplicate creations produced unhandled 500 crashes; `shift_start == shift_end` accepted; `created_at` violated schema. | Added Pydantic validators; stored UTC-aware datetime; caught `DuplicateKeyError` (409); formatted `created_at` as epoch ms. |
| 8 | `list_employees` | Off-by-one pagination (`skip = page * page_size` skipped the first page); `total` counted the whole collection, ignoring `department` filter; no sorting. | `GET /employees?page=1` returned rows 21–40; `total` mismatched filtered count; order non-deterministic. | Changed to `(page - 1) * page_size`; applied `q` to `count_documents`; sorted by `emp_code` ascending; formatted `created_at`. |
| 9 | `punch_in` | Non-existent employee caused `TypeError` (500) on `emp["shift_start"]`; check-then-act race allowed duplicate punches; returned internal `"id"` field; attendance date used naive `ts.date()`, ignoring overnight shift rule. | Non-existent employee returned 500; overnight punch-ins got wrong date; response included `id`. | Validated employee (404); computed date via `get_attendance_date`; caught `DuplicateKeyError` (409); removed `id`; formatted response. |
| 10 | `list_attendance` | Loaded whole collection into Python with `list(db.attendance_logs.find(q))`; sorted in Python; inverted date range did not return 422; returned `"id"` field; BSON datetimes not converted. | Memory crash on 100,000 documents; invalid ranges not rejected; schema violations. | Native MongoDB sort/skip/limit; validate `date_from <= date_to` (422); remove `id`; convert instants to epoch ms. |
| 11 | `MongoClient` | Initialised without `tz_aware=True`; datetimes read from MongoDB were timezone-naive. | Timezone ambiguity when converting to epoch milliseconds; tests relying on UTC-aware arithmetic could fail. | Added `tz_aware=True` to `MongoClient(...)`. |
| 12 | `GET /admin/explain/{endpoint}` was missing | The endpoint was declared in `openapi.yaml` with a `TODO` comment but not implemented. | Any request to `/admin/explain/...` returned 404. | Implemented the full endpoint with a hardcoded `frozenset` allowlist of five endpoint names; each branch rebuilds the exact same match/pipeline the live endpoint uses and calls `explain("executionStats")`; non-serialisable BSON types cleaned via `_bson_clean`. |

Also note anything you looked at and decided was **not** a defect, and why:
* **Identification by `emp_code` instead of `_id`**: Intentional per contract; `_id` must never be exposed.
* **No authentication or authorization headers**: Explicitly omitted per assignment scope.
* **Absence of DELETE or PUT endpoints**: The API contract specifies only punch-in, punch-out, and PATCH regularization.
* **Explain verbosity**: `db.command("explain", ..., verbosity="executionStats")` is used for both `find` and aggregation pipelines so that detailed execution metrics (docsExamined, keysExamined, nReturned, executionTimeMillis) are explicitly captured; the raw document is returned as-is per the contract's `additionalProperties: true` schema.
* **`department_summary` COLLSCAN on `employees.joined_on`**: An index on `joined_on` was added at startup; on the grader's dataset this converts to an IXSCAN for `joined_on <= month_end`. The `$lookup` into `attendance_logs` uses the `(emp_code, date)` index via `$$emp` variable binding.
